# 追踪开仓触发器设计

状态：已确认

版本：v1

更新日期：2026-09-29

## 1. 目标

追踪开仓触发器用于识别价格触及目标位后的快速反转，而不是在目标价直接接单。

以 ETH 做多为例：

1. 价格首次跌到 `2600` 时激活规则。
2. 从激活时刻开始，在固定时间窗口内持续记录最低价。
3. 价格从窗口内最低价反弹指定距离时触发开仓。
4. 超过时间窗口仍未完成反弹，则规则过期，不再开仓。

该模式的核心信号是“触价后在有限时间内完成反转”。回调距离和时间窗口均为策略参数。

## 2. 核心决策

### 2.1 固定总窗口

计时从价格首次满足激活条件时开始：

```text
deadline = activated_at + window_seconds
```

刷新新低或新高只更新极值，绝不重置 `activated_at` 或 `deadline`。

原因：

- 时间窗口表达原始触价事件的有效期。
- 如果每次刷新极值都重新计时，持续单边行情可让规则无限存活。
- 无限续期会把“快速插针反转”退化为普通的无限期回调单。
- 延迟很久后的反弹已不再属于原始交易假设，应重新评估并创建新规则。

### 2.2 截止边界

有效区间为闭区间：

```text
[activated_at, deadline]
```

时间戳恰好等于 `deadline` 的行情仍可触发；严格晚于 `deadline` 的行情使规则过期。

### 2.3 极值更新时间不控制总窗口

v1 不使用“最新极值形成后的独立回调窗口”。如果后续需要更严格地限定反弹速度，可增加第二个参数：

```text
retracement_window_seconds
```

该参数可以在刷新极值时重新计时，但仍必须受固定总窗口约束：

```text
triggered_at <= deadline
triggered_at - extreme_updated_at <= retracement_window_seconds
```

第二时钟属于后续增强，不改变 v1 的固定总窗口语义。

## 3. 参数

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | string | 规则唯一标识；可由服务生成 |
| `symbol` | string | 标准化交易对，例如 `ETHUSDT` |
| `direction` | enum | `long` 或 `short` |
| `activation_price` | decimal | 首次激活规则的价格 |
| `retracement` | decimal | 从窗口极值反向移动的绝对价格距离 |
| `window_seconds` | int64 | 从首次激活开始计算的固定总窗口 |
| `quantity` | decimal | 传递给执行服务的下单数量 |

价格和数量必须使用精确十进制，不得使用二进制浮点数。

## 4. 做多规则

定义：

- 激活价：`A`
- 回调距离：`R`
- 当前价格：`P(t)`
- 激活后的窗口最低价：`L(t)`
- 激活时间：`t0`
- 截止时间：`D = t0 + T`

### 4.1 激活

```text
P(t) <= A
```

首次满足条件时：

```text
activated_at = t
deadline = t + T
extreme_price = P(t)
status = tracking
```

### 4.2 更新最低价

在 `t <= D` 时：

```text
L(t) = min(L(t-1), P(t))
```

更新最低价不得改变 `deadline`。

### 4.3 触发

在 `t <= D` 时：

```text
P(t) >= L(t) + R
```

满足后生成买入执行请求，并记录：

```text
triggered_at = t
trigger_price = P(t)
```

## 5. 做空规则

做空逻辑与做多严格对称。

定义窗口最高价 `H(t)`：

### 5.1 激活

```text
P(t) >= A
```

### 5.2 更新最高价

```text
H(t) = max(H(t-1), P(t))
```

更新最高价不得改变 `deadline`。

### 5.3 触发

```text
P(t) <= H(t) - R
```

满足后生成卖出执行请求。

## 6. 示例

规则：

```json
{
  "id": "eth-long-2600",
  "symbol": "ETHUSDT",
  "direction": "long",
  "activation_price": "2600",
  "retracement": "10",
  "window_seconds": 60,
  "quantity": "0.5"
}
```

行情：

| 相对时间 | 价格 | 结果 |
| --- | ---: | --- |
| `0s` | `2600` | 激活；deadline 固定为 `60s`，最低价为 `2600` |
| `20s` | `2588` | 最低价更新为 `2588`；deadline 不变 |
| `50s` | `2575` | 最低价更新为 `2575`；deadline 不变 |
| `60s` | `2585` | 恰好反弹 10 点，在截止边界触发 |

反例：

| 相对时间 | 价格 | 结果 |
| --- | ---: | --- |
| `0s` | `2600` | 激活 |
| `50s` | `2575` | 刷新最低价，deadline 仍为 `60s` |
| `65s` | `2585` | 已超过 deadline，规则过期，不开仓 |

禁止将第二个示例的 deadline 重置为 `110s`。

## 7. 状态机

```text
waiting
  -> tracking
  -> dispatch_pending
  -> dispatching
  -> dispatched
```

异常和人工操作：

```text
tracking -> expired
waiting/tracking/dispatch_failed -> canceled
dispatching -> dispatch_failed
dispatch_failed -> dispatching
```

终态：

- `dispatched`
- `expired`
- `canceled`

终态规则不得因后续行情重新激活。需要再次交易时必须创建新规则。

## 8. 行情时间语义

- 判断窗口必须使用行情源的事件时间 `observed_at`，统一为 UTC。
- 同一规则只接受严格晚于 `last_observed_at` 的行情。
- 重复或乱序行情必须忽略，不能回写极值或延长窗口。
- 激活行情如果直接跳空越过激活价，以实际观察价格作为初始极值。
- 激活行情只负责建立跟踪状态，不在同一个行情事件内同时完成回调触发。

## 9. 执行语义

- 做多规则触发 `buy`，做空规则触发 `sell`。
- v1 生成 `market` 类型的执行意图，实际执行仍受执行服务风控约束。
- 每条规则使用固定幂等键：

```text
trigger:{rule_id}
```

- 重试不得生成新的逻辑订单。
- 触发价格是行情参考价，不保证等于最终成交价。
- 执行服务必须独立检查允许交易对、最大名义金额、信号时效和授权状态。

## 10. 失败处理

- 执行服务不可用时，规则进入 `dispatch_failed`。
- `dispatch_failed` 可以人工或任务调度重试，但继续使用原幂等键。
- 规则过期后不得重试行情触发。
- 服务重启后必须恢复规则状态、deadline、极值及派发状态；当前内存实现尚不满足该生产要求。

## 11. 验收条件

必须覆盖以下测试：

1. 做多规则首次跌到激活价时启动固定窗口。
2. 做空规则首次涨到激活价时启动固定窗口。
3. 新低更新做多极值，但 deadline 不变。
4. 新高更新做空极值，但 deadline 不变。
5. 回调值恰好达到阈值时触发。
6. 时间戳恰好等于 deadline 时允许触发。
7. 时间戳严格晚于 deadline 时过期。
8. 刷新极值不得延长总窗口。
9. 重复和乱序行情不得改变状态。
10. 同一规则只能生成一个逻辑订单。
11. 派发失败后的重试保持相同幂等键。
12. 终态规则不得被后续行情重新激活。

## 12. 非目标

v1 不负责：

- 判断激活价、回调距离和时间窗口是否具有交易优势。
- 根据 ATR、波动率或盘口自动计算参数。
- 保证触发后立即浮盈。
- 将窗口内极值到触发价之间的移动计入收益。
- 绕过执行服务直接连接交易所下单。
